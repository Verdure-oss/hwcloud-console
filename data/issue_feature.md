# 建议任务列表接口支持按周期类型筛选

## 背景

新版成长中心（grow.developer.huaweicloud.com）的任务清单页已支持按「全部 / 每日 / 每周 / 每月 / 一次性」分类展示，但对应接口
`GET /api/v1/hdgrowservice/servlet/tasks` 并没有周期过滤参数，前端只能一次拉全量再由浏览器侧过滤。

任务总量现在虽然只有 10 条左右，但接口已经支持 `page_no` / `page_size` 分页，说明设计上是按「任务会持续增长」来考虑的。等到每月任务、一次性任务继续累积，全量拉取的开销会逐渐显现。

## 期望功能

希望 `/servlet/tasks`（以及需要登录态的 `/user/tasks`）支持一个可选的周期过滤参数，例如：

```json
{
  "cycle_type": "WEEKLY",
  "page_no": 1,
  "page_size": 20
}
```

取值与现有 `cycle_type` 字段保持一致，即 `DAILY` / `WEEKLY` / `MONTHLY` / `LIMIT`。传入后服务端只返回该周期的任务，`total` 同步反映过滤后的数量。

## 使用场景

- 成长中心页面的「每周任务」标签页可以直接请求服务端，无需先拉全量再本地筛选
- 第三方集成（比如把任务同步到自己的待办列表）只关心某个周期时，可以避免解析无关数据
- 分页场景下，过滤后每页的有效数据占比更高，减少无效请求

## 补充说明

建议把该字段设计为**可选**：不传时保持当前「返回全部周期」的行为，对存量调用方完全兼容。

如果实现上更倾向在客户端过滤，也可以考虑在响应里直接给出各周期任务数的统计字段（如 `daily_count` / `weekly_count` / `monthly_count`），这样前端渲染分类标签上的数字时，不必为了计数再拉一次全量。
